# 个人助手系统手册
**PAS — Personal Assistant System**
版本：v3.0 | 状态：草稿

---

## 一、这是在做什么

PAS 是一个以「状态召回」为核心目标的个人助手系统。

它不是知识管理工具，不是任务管理系统，不是笔记软件。它是一个有记忆的对话伙伴——能随时聊、能在对话中主动浮现相关的历史语境、能在你需要的时候把「当时咋想的」那个状态调回来。

这个系统存在的前提是：你是一个想法活络、跨域联想、不爱刻意整理的人。系统的设计必须顺着这个现实，而不是试图改变它。

---

## 二、核心目标

**首要目标：状态召回**
不是找到一条信息，是找回一个现场——当时在想什么、被什么触发、思路往哪走、说了没说完的那句话。

**次要目标：连续性与交流**
每次对话不从零开始。系统知道你是谁、在关注什么、最近在想什么。书籍作为原材料的一部分进入系统，不只是为了检索，而是让对话能以你读过的东西为基础展开——它是交流的背景，不是查询的数据库。

**衍生目标：被动触发**
你不需要记得有某个旧想法存在。系统在你聊天的过程中，发现当前话题和历史记录的连接，主动把它浮出来。

---

## 三、一个根本区分

**信息 vs 状态**

信息可以脱离你独立存在。「孟子说过什么」写下来就是它自己，谁读都一样。

状态不能独立存在。「我当时咋想的」是一整套东西的组合：当时的关注点、触发源、情绪方向、没说完的半句话。它是一个现场，不是一个条目。

这个区分决定了系统的所有设计选择：
- 为什么原版必须保全——状态只活在未经处理的原始材料里
- 为什么处理层要做薄——处理得越多，失真越多
- 为什么不强求分类——你的想法是流动的，强行分类会切断跨域连接

## 三·五、双层架构：状态层与知识层

v3.0 新增了知识层，系统从单层变为双层。这是整个系统最重要的结构变化，需要先把两层的根本区分说清楚。

### 为什么是两层

把「遇到一条网上碎片」走一遍就能看出问题：不存会忘；塞进 pool 会污染池子密度，而且骗不到状态召回——碎片不带你的状态，没有现场可召回；存进收藏夹等于没存。这是 pool 层满足不了的真实需求。

但更根本的原因是：**状态和知识对「改写」的要求正好相反**。状态一改写就失真，知识不改写就是死的收藏夹。两者物理上没法共处一层。

### 两层对照

|  | pool 层（状态层） | 知识层 |
|---|---|---|
| 处理对象 | 你自己产生的思考 | 别人的知识碎片 |
| 带不带你的状态 | 带（核心就是它） | 不带（干的知识） |
| 召回目标 | 找回「当时怎么想的」现场 | 找到「这个知识点和什么有关」 |
| 能不能被改写 | 绝不（原版保全） | 可以（综合、链接、提炼正是它的价值） |
| 单条价值 | 高密度，自成一篇 | 低密度，单看没头没尾 |

### 知识层的核心认知

**价值是滞后兑现的。** 碎片一开始孤立是常态，不是缺陷。岛屿是长出来的——某天第 N 个碎片进来，突然和三个月前那个孤点接上，连接就在那一刻浮现。不能用早期表现判断这层有没有用，头一两个月「一盘散沙」是正常潜伏期。

**核心机制是新碎片回填老连接。** 连接是后来才长出来的，不能在入池时把关系一次性算死。这是知识层和静态收藏夹的根本区别——它是活的，会生长。（注：系统性回填属 Phase 3，当前 Phase 1 只做消化时当场建链。）

### 知识层的风险

知识层比 pool 层多了「CC 可以改写」的权限。这是它的价值，也是它的风险——CC 综合错了或综合平庸，这层会慢慢变成你不信任的东西。

最隐蔽的退化形式是**过度平滑**：幻觉复利不只来自无中生有，更来自反复改写。「核心」区每加一条新碎片就被重新综合一次，迭代多次后，早期那些有棱角的洞察，容易在一次次「提炼」中被磨平，最后剩下一段正确但平庸的废话。这比凭空捏造更难察觉，因为每一步看起来都合理。

三道闸防它：碎片来源留痕（可溯源）、入层门槛（不进垃圾）、**以及你得真的去看**。知识层不像 pool 可以放着等召回，它需要你偶尔翻翻 concept 页，看 CC 综合得对不对。不看，它会悄悄烂掉。

**结论：知识层需要你保持轻度参与，不是全自动外脑。**

### 两层的咬合

两层物理隔离、检索不隔离——CC 回答实质问题时两层都查，合并结果呈现给你。跨层链接方向单向：知识层可以链向 pool，pool 不被反向改写（pool 的链接只有你能建）。

## 四、理论框架

### 4.1 池子模型

系统的存储核心是一个「池子」——所有原材料按时间顺序堆在一起，不预先分类。

每条记录带以下元数据（写入 Obsidian 属性区）：
- 时间戳（date）
- 一句话标记（title）
- 来源类型（source_type）
- 标签（tags）——聚类的主要手段，从 ROOT.md 的词库中选取
- 状态摘要（summary）——简短描述这条记录的思维状态：卡在哪、哪里没说完、从哪跳到哪没接上。闭合的内容如实写「结论完整」即可

书籍单独存放，不进主池子。原因：书籍是别人的思想，混入会稀释你自己产生的内容。

池子里的原材料来源不同、密度不同，但不做硬性隔离。跨类型的连接是系统最有价值的能力，不应被场景隔离切断。

### 4.2 原版保全原则

任何进入系统的内容，原版必须完整保留，不得被提炼或改写替代。这里的「原版」指**内容原版**，不是文件格式原版——docx 转成 Markdown 存入池子没问题，但绝不允许改写、删减、总结内容本身。

处理层只允许做一件事：在原版之上加标记和索引（属性区字段、标签、摘要）。不改写内容本身。

原因：你和自己想法之间隔的东西越多，状态召回的质量越低。被总结过的想法会失真——读摘要时你以为自己回到了当时，其实只是在读一个关于当时的描述。

「想清楚了」不等于旧记录失效。当你对某个旧疑问得出结论时，新结论作为新记录独立存入池子，旧记录原版保留。新旧记录并排存在，记录的是你从疑问走到结论的完整轨迹。

**原版保全只约束 pool 层，不约束知识层。** 这不是破例——是两类对象本就该有两套规则。

### 4.3 轻分类原则

系统不强制分类，不建立复杂的目录结构。

参考框架（PARA）可以作为粗粒度的辅助：
- Projects：当前活跃推进的事
- Areas：长期关注的领域
- Resources：书籍、参考资料
- Archives：已沉寂的内容

但这个框架是描述性的，不是强制性的。新内容进来，系统自动判断归属，你不需要手动操作。

### 4.4 标签与链接

标签和链接是系统的两种结构索引，职责不同。

**标签（tags）** 是聚类的主要手段。同一标签下的笔记在 Obsidian 里天然聚合。标签前后兼容——今天给任何一篇笔记加一个标签，它立刻和过去所有同标签笔记归到一起，不受入池先后顺序的影响。CC 入池时自动从 ROOT.md 的标签词库中选取，词库中没有合适的才造新词。

**链接（`[[...]]`）** 在 pool 层和知识层的规则相反：pool 层的链接由你手动建，携带着「你当时注意到了这个关联」的判断；知识层的链接由 CC 建，它只是知识的组织手段，不携带你的状态。两套规则方向相反且都成立，不是不一致——是两类对象的正确投影。

跨层链接单向：知识层可以链向 pool，CC 不反向进 pool 文件加链接。Obsidian 反向链接面板会自动让 pool 那篇显示「被某知识页引用」，无需也不允许 CC 动 pool 文件。

### 4.5 双模调用

**主动检索**：你想起来有某个旧想法，主动问系统，它去池子里找，返回原版。

**被动触发**：你正在聊某个话题，系统发现当前话题和历史记录有连接，主动浮出来——「你之前有个相关的想法/记录，要看吗？」

两种模式同时存在，互相补充。被动触发解决的是「根本想不起来有这个东西存在」的问题，主动检索解决的是「想起来了但找不到」的问题。

### 4.6 被动触发的链条：按需三级

被动触发不靠预先算好的分数公式，靠 CC 作为在场的判断者当场决定。

系统不预先计算排序分数、不使用加权公式。原因：预先算分是「浮现时刻没有判断力在场」时的替代品；PAS 的执行者 CC 本身就是一个会思考的模型，能在浮现时刻直接读材料、做判断。把联想和筛选交给模型当场做，比用一个算术公式近似判断更准、也更灵活。

这意味着系统的「优化旋钮」是协议文件里的自然语言说明，而不是需要调校的数字阈值。浮现不准时，修改协议中对 CC 的指令即可——这是你能读懂、改得动的优化方式。

**三级按需触发：**

- **一级·圈候选**：CC 根据当前话题，通过标签 + 手动链接 + Mem0 语义检索，拉出一批可能相关的笔记。此时 CC 只看 title 和 tags，做最粗的相关性判断。不够就换一批标签再找。
- **二级·读摘要**：对一级筛出的候选，CC 读 summary（状态摘要），判断哪几条值得深入。
- **三级·读全文**：话题确实需要深入时，CC 去调对应笔记的全文来读，做最终判断是否浮现。

三级不是同一次判断里的三步漏斗，而是随对话推进**按需触发**的三次动作。一级随时在跑，二级有苗头才做，三级话题真正深入时才做。

### 4.7 分层上下文

系统对 CC 的上下文采用分层加载策略：

- 根层：一个轻量文件（ROOT.md），描述你是谁、当前活跃的关注点、标签词库
- 项目层：各个活跃方向的具体背景，按需加载
- 原材料层：池子里的具体内容，只在需要深入检索时加载

原因：上下文窗口是有限资源。把所有东西全塞进每次对话，反而会降低召回质量——模型对中间部分的注意力会显著下降。

### 4.8 本时期回顾

v3.0 新增机制。在此之前，ROOT.md 里的用户画像从无更新机制——入池流程结束后，没有任何节点让 CC 回头判断「这批内容有没有改变我对用户的理解」。画像更新是一句没有触发机制的悬空声明。

本时期回顾是对这个空白的回答。机制不靠定时任务、不靠阈值计数，靠一个简单的环：

入池时留痕 → 用户某天想起来看 → CC 出报告 → 聊或不聊 → 成品入池 → CC 给删留建议

**四个设计决定：**

入池时追加记录是纯记录动作，CC 不主动提议做回顾——CC 没有常驻感知能力，主动提议会变成无效声明或打扰，回顾由用户发起。

报告是「状态回看」不是内容摘要——写这段时间池子里在动的几条线，卡在哪、哪个旧判断松动了、哪条新线还没接上。

两种走向机制不预设：用户读完不想聊，报告独立存档；用户想聊，报告作为对话开头，整场合存一份。走向由用户当下状态决定。

**画像更新是回顾过程中可能掉出来的副产品，不是这个环的目的。** 以画像更新为目的会让整个环变得功利且难判断成败。两个自然时机：CC 出报告时对照画像发现某处被新内容证伪或松动；用户和 CC 聊报告的过程中浮现「画像该改了」。两种时机都行，但都要用户拍板，CC 顺手改。

## 五、架构分工

系统中有四个角色，职责严格分离：

**CC（执行者）** ——唯一的判断者。负责入池处理（转格式、加属性区）、知识层消化、检索时的联想判断、被动触发时的浮现决策。所有需要「理解内容」的事都由 CC 做。通过 Claudian 插件在 Obsidian 内部工作。

**Obsidian（存储）** ——本地 Markdown 库，存原版内容。标签聚合、反向链接、图谱视图都是 Obsidian 提供的——图谱是你看自己思维网络的地方，CC 不使用图谱。

**Mem0（语义检索）** ——存每条笔记的语义向量（通过嵌入模型生成），加上文件路径等元数据。CC 问它「和这段话相关的有什么」，它返回候选的文件路径和摘要。Mem0 不判断、不联想——它是 CC 用来查的工具。pool 和知识层使用独立的 Qdrant collection，物理隔离但检索时并行，CC 合并结果后统一返回。

**标签 + 链接（结构索引）** ——标签聚同类，链接在 pool 层由你手动建、在知识层由 CC 建。两者共同作为一级候选的来源，和 Mem0 的语义检索互补。

一句话：CC 思考，Obsidian 存储，Mem0 检索，标签和链接提供结构。

## 六、原材料来源

系统接收四类原材料：

| 来源 | 优先级 | 说明 |
|------|--------|------|
| AI 对话记录 | ★ 最高 | 最密集的思维痕迹，优先建立导出流程 |
| 语音/文字随手记录 | 高 | 手机随时捕捉，低摩擦 |
| 已有文档 | 中 | 一次性导入，历史材料 |
| 书籍 | 独立 | 单独存放，不混入主池子。作用是交流背景，而非检索对象 |
| 外部知识碎片 | 知识层 | 别人的知识碎片，走知识层入层流程，不进 pool |

**关于历史材料**：过去散落在各平台的对话不追溯。系统从现在开始建，往前追代价过高且意义有限。

## 七、设计原则总结

1. **顺势而为**：系统设计顺着你的真实习惯，不要求你改变行为模式。特别是：系统的复杂度必须压在你能维护的程度——一个你调不动的系统等于没有系统。
2. **原版保全**：状态只活在未经处理的原始材料里，绝不以提炼替代原版。「原版」指内容原版，不是文件格式原版。此原则只约束 pool 层。
3. **轻分类**：分类是辅助，不是负担。标签聚类，系统自动处理，你不手动归档。
4. **本地优先**：数据在你自己的机器上，不依赖第三方服务器，数据主权在你。
5. **薄处理层**：宁可调用时慢一点让 CC 多读原文，也不愿事先把想法嚼碎。
6. **双模并存**：主动检索和被动触发同时运行，互不替代。
7. **判断归模型**：不预先算分、不用加权公式。联想和浮现的判断由 CC 当场做，优化手段是修改协议里的自然语言指令。
8. **两层两套规则**：pool 原版保全，知识层允许改写。两套规则方向相反，各自在自己的对象上成立。

## 八、实现路径

**存储层**：Obsidian 本地库，纯 Markdown 文件，数据完全自有。通过 Claudian 插件在 Obsidian 内部与 CC 交互。
**记忆层**：Mem0（GitHub：mem0ai/mem0），从第一天起存储每条笔记的语义索引（title、summary、标签、链接信息），用于快速检索。pool 和知识层使用独立的 Qdrant collection，物理隔离。原版内容始终保留在 Obsidian 里——Mem0 发现连接、返回路径，CC 去 Obsidian 调原版。两者分工：Mem0 管检索，Obsidian 管保真。
**对话导出**：agoramachina/claude-exporter（Chrome 插件），支持 Claude 等主流平台，导出为 Markdown 格式直接入库。
**处理层**：CC 负责读取原始文件，转 Markdown，自动打标签、写状态摘要、建索引，不改写原文内容。知识层由 CC 消化建 concept 页，允许综合改写。具体规则写入系统协议（CLAUDE.md）。
**调用层**：CC + 系统协议分层加载。根层描述你是谁和当前关注点，项目层按需加载，原材料层仅在深度检索时调用。

## 九、分阶段建设

### pool 层阶段

#### 阶段一·跑通核心闭环

**目标**：内容能进来、检索能用、系统是活的。

- 装 Obsidian + Claudian + Mem0，建好库结构，放协议文件和 ROOT.md。
- 喂第一批原材料（docx 文章），CC 走完整流程：转 Markdown → 加属性区（title / date / source_type / tags / summary）→ 同步 Mem0 → 原件留档。
- 在真实文件上验证属性区字段够不够用，不合用当场改协议。
- 验证闭环：丢一个话题，CC 能通过「标签+链接圈候选 → 读摘要 → 必要时读全文」找到相关旧笔记，判断准确。

**【阶段门槛 G1】** 10-15 篇真实内容干净入池，属性区经真实验证并固化，你信任 CC 的检索和判断。

#### 阶段二·被动触发

**目标**：CC 主动拍你肩膀。

- 在你聊天时，CC 主动感知当前话题与池子的连接，按三级链条判断是否浮现。
- 浮现时给出原版入口，不用转述代替。
- 核心要调的是「什么时候浮、浮多少」——前期从严，宁缺毋滥。调的手段是修改协议中的自然语言指令。

**【阶段门槛 G2】** 浮现时机恰当、频率不烦人、内容有价值。

### 知识层阶段（与 pool 层并行推进）

#### Phase 1·物理层 + 入池消化 + 检索

**目标**：碎片能存、能消化、能被检索到。

- 建 `知识/` 文件夹结构（`_inbox/`、`_待定/`、`concepts/`、`index.md`）。
- 为知识层配置独立 Qdrant collection，pool 的 collection 不动。
- CC 能执行消化流程：inbox → 判断接哪 → 建/更新 concept 页 → 接不上移入 `_待定/`。
- 检索时两层并行，CC 合并结果统一返回。

**验证重点**：知识层检索不污染 pool 状态召回。

#### Phase 2·跨层链接

**目标**：岛屿开始成形，两层真正长在一起。

- concept 页之间建 `[[]]` 链接。
- 知识层向 pool 建跨层链接（单向）。
- 触发条件：积累 10 个以上 concept 页，跨 3 个以上话题域。

#### Phase 3·新碎片回填老连接

**目标**：知识层从「concept 仓库」变成真正的知识网络。

- 新碎片进来时，CC 回头扫描已有 concept 页，发现语义上能接上的就补链接。
- 这是知识层「岛屿生长」机制的核心实现。

#### Phase 4·主动提示

**目标**：PAS 从记忆系统变为认知辅助系统。

- CC 在消化或答问时，主动发现矛盾、空洞、重复、缺环，并提醒你。
- 把外脑从「被动应答」变成「会指方向」。

**当前进度**：pool 层 G1、G2 已达标，知识层处于 Phase 1。

## 十、当前状态与边界

**已确定的**：
- 系统目标和核心设计原则
- 双层架构（pool 状态层 + 知识层）及其根本区分
- 架构分工（CC 判断、Obsidian 存储、Mem0 检索、标签+链接结构索引）
- 被动触发链条（三级按需、判断归模型、无预算分公式）
- 标签与链接的定位（pool 层标签主聚类、链接手动点对点；知识层链接 CC 建）
- 原材料来源和优先级（新增知识层入口）
- 存储策略（本地优先，Obsidian + Markdown；双 collection 物理隔离）
- 处理层策略（pool：原版保全 + 加属性区；知识层：允许综合改写，来源留痕）
- Mem0 从第一天起使用
- 本时期回顾机制（入池留痕 → 用户触发回顾 → 报告/对话入池 → 删留建议）
- 画像更新走回顾闭环，不自动触发

**已知边界**：
- 知识层价值滞后兑现，Phase 1 初期「一盘散沙」是正常潜伏期，不是系统缺陷
- 知识层需要轻度参与（偶尔翻 concept 页），不是全自动外脑
- 被动触发的质量依赖池子的体量，初期效果有限，需要积累
- 知识层 Phase 3（回填）、Phase 4（主动提示）尚未启用

**搁置项（记录在案，暂不纳入）**：
- 长期问题池：系统识别你反复回到的根本问题，显现长期认知主线。有价值，当前阶段复杂度已够高。
- 类型化的知识层链接边（如区分「支持/反驳/延伸」等关系）：裸 `[[]]` 在当前体量够用，等岛屿长大再说。
