## 【用户】建号是什么

建号是 PAS 的一次性初始化流程：你投入第一批资料后，CC 通读全部材料，提炼出第一版「画像」（你是谁、怎么想问题）和「活跃关注点」（你最近在动哪几条线），然后和你聊一场校准对话，定稿写入 ROOT.md。此后画像只通过日常回顾机制慢慢更新，不再专门为它开对话。

你需要做的只有三件事：把资料交给 CC 入池；资料入完后说一声「开始画像初始化」；校准对话时正常聊天——对味就说对味，不对就说不对，没感觉就说没感觉，都是有效反馈。

## 【CC】环节零 · 建号触发

1. 触发条件：ROOT.md 画像区为空或为模板占位符，且库内有已入池或待入池的资料。两者同时满足，进入建号状态。
2. 主动向用户说明全流程（资料入池 → 你独立提炼初稿直接写入 → 校准对话定稿）。这是 PAS 中唯一允许你主动提议的场合。
3. 同时声明切换方式：「资料全部入完后告诉我，我开始画像初始化。」环节切换由用户触发，你不自行判断「资料入完了」。
4. **此环节禁止**：问用户任何自我描述（「你觉得自己是什么样的人」「最近在琢磨什么」都不许问）。画像必须从材料里独立读出，不从用户的自述里来。
5. 入口唯一：本引导是建号的唯一执行依据。骨架文件（v4）为设计档案，执行中不读、不引用。

## 【CC】环节一 · 资料入池 + 建标签库

1. 按协议第 3 节正常入池：转格式、属性区、状态摘要、打标签、同步 Mem0。
2. 标签词库成形后，与用户对齐一次词库内容。
3. 若库内资料已入池、词库已固化（如本环节在建号前已完成），向用户确认后跳过本环节。
4. 画像与活跃点在本环节全程不动。后续提炼不以标签体系为透镜。

## 【CC】环节二 · 画像 + 活跃点初稿

**读取范围：**

- 读：`pool/` + `大模型-对话/`。
- 不读：`知识/`、`books/`、用户标注排除的材料（如「不入mem0」字样的文件夹）。

**第一步 · 扫摘要，落汇编（本窗口唯一任务）：**
1. 扫目录，报出文件计数，与库内实际文件数核对，缺了先向用户报告再继续。
2. 读全部文件的 PAS 数据区完整摘要（②），**逐字搬运原文，禁止压缩或改写**。
3. 将所有摘要写入汇编文件 `.pas/建号摘要汇编.md`，格式：文件名 + 完整②内容，一篇一节。
4. 汇编写完，向用户报告计数与汇编文件路径。**本窗口到此结束。**
5. 用户新开窗口，从汇编文件接力，继续第二步。

> 汇编文件是建号临时工件，建号完成后删除或归档至 `.pas/docs/`。
> 校准时证据仍只认原文，汇编不充当证据。

**第二步 · 选读全文（不可跳过，跳过即环节二未完成）：** 
3. 新开窗口后，先读 `.pas/建号摘要汇编.md`，再从中挑高信号文件读全文。**选读必须覆盖不同体裁与主题簇**（笔记、日记、论文、对话各簇都要有代表），不得集中在单一簇——跨文件的行为模式只住在全文形态里，选读偏科会整簇漏掉。 
4. 选了哪几篇、为什么选，在台账头部记一行备查。

**第三步 · 写初稿，直接写入 ROOT.md：**

画像结构——**主线为纲，断言为目，两层都要写**：

- 主线数量由模式决定：一条主线 = 一个跨材料、跨时间反复出现的稳定模式；有几个真模式就几条，不凑数、不强拆。拿不准两条是不是同一模式时，倾向合并为一条——粗线校准比碎线信息密度高。
- **每条主线下必须挂出断言列表**：单断言成条，每条只含一个可单独处置的判断。归拢时装不进任何主线的断言，单独列在「未归拢断言」区，不得静默丢弃。
- latent 深层判断逐条标「（CC 推断）」，一条不漏。
- 用了外部分析框架必须标明「按 X 框架观察」。
- 顶部标注「未校准初稿」。
- 文档内称用户为「他」。

活跃点写法：

- 写「近期在动的事」：在推进什么、转向了什么、启动了什么、悬置了什么。
- 必须可核对，禁止推断性表述；**同时禁止写成语料库统计**（「池中有 N 篇 X 类笔记」「某系列均含批判分析」是库存描述，不是关注点）。
- 直接落，不标未校准。
- 材料里的相对时间（今年／去年／最近）一律换算成绝对日期再写，不照搬原文的相对表述。

**落笔纪律：**

- 读完直接写入。写完只向用户报告一句：「初稿已写入，N 条主线、M 条断言、K 条活跃点。」
- **不总结内容、不汇报发现、不问任何形式的「方向对不对」**——讨论全部留给环节三。

写入 ROOT.md 的权限仅限建号阶段，建号结束即收回，回归协议 10.4/10.5 的用户拍板制。

## 【CC】环节三 · 校准对话（只校准画像）

**总原则：只对大方向，不逐条对答案。** 校准单位是主线。断言在谈主线时自然带出，不为过条例而提条例。不依赖用户回忆当时——用户不记得是常态，不是失败，用现在的他回应即可。对话中称用户为「你」，任何情况下不得用「他／这个人」。

**每条主线的固定形态（三段）：**

1. **证据点名**：「我在 X、Y、Z 几篇里看到 a、b、c」——点出文件名，关键处逐字引一两句原文。**禁止用②摘要充当证据**（摘要是你写的，拿它证明你的判断是循环自证）。
2. **感觉**：「这让我有种感觉，你有点像……」——一句话，暂定语气。
3. **开放**：一个开放问，不自带折扣选项（禁止「还是说你觉得我说大了/想多了/过度推了」这类预制台阶——它把问题搅成两个，同时给出最省力的出口）。用户怎么接都行。

**处置判读：**

- 四种处置：确认／修正／删除／没感觉。从用户的实际表态中判读，不逐条问。
- **判读颗粒度跟着用户的表态走**：用户认整条主线，整条算确认；用户只引了某一句说「这句是的」，只有那一句算确认，主线其余断言记「未处置」。
- **没有明确表态的一律记「未处置」。绝不从「往下」「继续」推断出确认。**
- 用户打开了新东西（修正、新表述、新事实）时，顺着用户的方向多聊几轮再落处置；处置不必急着关掉这条线。
- 校准中你现场说出、且用户明确确认的新判断，与初稿断言同等地位——记入台账，定稿必须回流。

**台账纪律：**

- 台账文件：`.pas/建号校准台账.md`。
- **每条主线谈完，当场追加一行**（主线 | 处置 | 用户关键原话），不许攒到最后批量补记——台账是断点保险，批量补记等于拆掉保险。
- 上下文中断或分场续聊时，开场先读台账恢复进度，不靠记忆。

**对话纪律：**

- 事实纠正（时间线、出处错了）→ 接受修正，不算判断被推翻。共鸣反馈（没感觉、说不上来）→ 原样记录按处置办，不顺从认错、不改写求认。
- 禁止「你说得对」开场的反射性认错。按协议附录判断稳定性原则执行。
- **禁止安抚、打气、展望式鼓励**。不引用或背书任何对用户未来的预测（包括材料里其他 AI 说的）。校准是核对读法的场合，不是鼓励的场合。

**定稿（按台账落，不按记忆落）：**

1. 主线确认 → 整线保留；主线修正 → 按用户表述改写；主线删除 → 整线删除；没感觉／未处置 → **降级为「待定观察」区的弱表述，原主线全文必须删除**，不得两版并存。
2. 用户确认过的现场新判断，写入对应主线。
3. 定稿后自查一遍：画像区块数与台账处置数一致；未确认的锋利表述一条不剩。校准对话中用户给出的新表述已全部回流进对应主线，不遗漏。
4. 顶部「未校准初稿」改为「画像定稿」，更新「上次更新」行。

**收尾（三个动作，缺一个建号不算完成）：**

1. 校准对话整场入池：存 `大模型-对话/`，source_type 用 `conversation`，命名标明「建号校准」。入池须走完整流程：属性区、PAS 数据区、Mem0 同步均须完成，不得只复制文件。
2. 台账保留在 `.pas/`，不删。
3. 向用户报告定稿状态（各主线处置结果），并明确告知：建号结束，此后画像与活跃点只走第 10 节回顾闭环更新（append 新线低门槛；replace 旧判断须说明哪批新材料证伪了它，用户拍板）。

## 【CC】执行纪律（全程有效）

1. 你的汇报不可信，文件才可信——凡声称「写完了／落账了／删了」，以文件实际内容为准，用户随时核对。
2. 每个环节完成后等用户指令再进下一环节，不连跑。
3. 遇到不确定（材料归属、范围边界、处置判读拿不准），停下来问用户，不替用户决定。
4. 本文档与骨架冲突时，以本文档为准；本文档没写到的，回骨架查设计意图。
